# PlanCraft review — November 2026

This review covers bugs, gaps and missing features in PlanCraft, measured against professional desktop planners (Microsoft Project, and Asana-style work management). The review was read-only: the code was read in full, the suspected engine and I/O bugs were reproduced in a scratch crate, and the workspace tests were run.

**Fixed since the review:** P0 bugs 1–9 and bug 19 (recovery copies while idle), plus MCP undo/redo attribution. Each has a regression test. Bug 6 is mitigated: network-share links are not followed automatically on open, and non-regular files are refused.

**Scheduling bugs:**
- Bugs 10–17 are fixed. Bugs 12, 13 and 16 have parity tests that cite Microsoft's pages. The others have regression tests in `scheduling.rs`.
- Bug 12 covers only what Microsoft documents: a Start No Earlier Than constraint and a deadline on a summary task.
- Bug 16 still ignores the status date for actual cost.
- Bug 18 (FF/SF links to a summary) is unchanged, because no official Microsoft source describes the behaviour.

**Performance bugs 24–27 are fixed.** The speed gate (`tests/speed.rs`) now covers the slow cases:

| Case | Before | After |
|---|---|---|
| Linking a 2,000-task chain | 28.6 s | 0.19 s |
| Recalculating 2,000 tasks with one date in 2299 | 10.7 s | 29 ms |
| Leveling 1,000 tasks | 10.0 s | 1.37 s |

- The new leveler gives identical results to the old one on the comparison scenarios.
- Undo history has a 256 MiB memory budget per document.

**Features since the review:**
- Custom fields: text with a pick-list, number, cost, date, duration and flag. They can be edited in the table and in Task Information, are exported to CSV, and have four new MCP tools.
- A column menu on table headers: insert, hide, move and reset columns, saved with the plan.
- Sorting within the outline, by clicking a header or from the View tab.
- Grouping by any field, with group headers and bars.
- CSV export now guards against formula injection and starts with a UTF-8 BOM.
- Printing: a Print window (Ctrl+P) with a live preview, Page Setup saved with the plan, printing through the system print service, and PDF export from the app and over MCP (`export_pdf`, `set_page_setup`). The PDF writer is PlanCraft's own (pure Rust) and embeds a subset of the bundled UI font.

**State of the build:** `cargo test --workspace` passes. No parity tests are marked `#[ignore]`.

**Severity key:**
- **P0:** data loss, security, or a headline feature that is broken.
- **P1:** wrong results the user will notice.
- **P2:** minor issues and polish.

✅ means the bug was reproduced. 📖 means it was confirmed by reading the code.

## 1. Bugs

### P0: fix first

| # | Area | Problem | Where | Repro / scenario |
|---|---|---|---|---|
| 1 | MCP attach | The `--attach` bridge (the recommended Claude Code setup) fails on any reply of 32 KiB or more. tiny_http switches to chunked encoding at that size, and `post()` doesn't decode chunks. ✅ | `plancraft-mcp/src/attach.rs:105` | `tools/list` (73 KB) returns "PlanCraft is not reachable: trailing characters…", and so does `get_schedule` on a mid-size plan. Fix: send HTTP/1.0, decode chunked replies, or raise the server's chunk threshold. Add a test with a large reply. |
| 2 | App dialogs | Dialogs write to whichever document is active, not the one they were opened for. The windows are non-modal and `TaskId`s repeat across documents. 📖 | `app.rs:1308-1349`, `project_info.rs:60` | Open Task Info in doc A, switch to the tab for doc B, press OK, and B's task with the same id is overwritten. The same happens with Project Info, Working Time and Resource Info, or when an agent switches the active doc. |
| 3 | App clipboard | Ctrl+C, Ctrl+X and Ctrl+V never fire. egui-winit turns them into `Event::Copy/Cut/Paste` and emits no `Key` event, so `consume_shortcut` never matches. 📖 | `app.rs:158-160` | Select a task, press Ctrl+C then Ctrl+V: nothing happens (the toolbar buttons work). The kittest tests inject `Key` events, which hides this. |
| 4 | Grid editing | Committing a cell without changing it still changes the data. 📖 | `grid.rs:539-555`, `gantt.rs:85-91`, `columns.rs:264, ~348` | **Start/Finish:** clicking into a cell and away adds an SNET 08:00 constraint, or moves a manual task. **Notes:** this keeps only the first line and deletes the rest. **Duration:** drifts by 2-decimal rounding (75 min becomes 77 min). Each of these adds an undo step. Fix: skip the commit when the text equals the original. |
| 5 | Save As | A failed Save As leaves the external-link paths rewritten for the folder that was never written. The next Save writes broken links. ✅ | `plancraft-core/src/workspace.rs:183-196` | Save As to an unwritable folder fails, then Save produces `../../../../plans/b.plancraft` and the links no longer resolve. Fix: rewrite a clone of the paths, or restore them on error. |
| 6 | Security | Opening an untrusted plan reads every path in `external_projects[].path`. On Windows a UNC path (`\\host\share\x`) makes the machine connect over SMB, which leaks the user's Windows (NTLM) credentials. On Unix a FIFO hangs the app while the workspace lock is held. 📖 | `workspace.rs:234`, `io.rs:347-385` | A plan received by email with a crafted path. Fix: don't refresh automatically on open (or ask first), and refuse UNC and device paths. |
| 7 | Agent safety | `close_project {discard_changes:true}` closes a dirty document in the app with no prompt. The next frame prunes its recovery copy, so the work can't be recovered. 📖 | `plancraft-mcp/src/tools/documents.rs:243`, `recovery.rs:186` | An agent can wipe unsaved user work. Fix: refuse `discard_changes` for documents with user edits, or keep the recovery copy. |
| 8 | Assign dialog | An invalid Units value removes the assignment, because `parse_units` returns `None` and `None` means "remove". 📖 | `dialogs/misc.rs:65, 79-85` | Type `abc` in Units, click Update, and the assignment is gone. |
| 9 | Concurrent writers | Saving doesn't check the file's modification time and takes no lock. A second app instance or a standalone `plancraft-mcp file.plancraft` silently overwrites the other's changes. 📖 | `io::save`, `Document::save` | Two writers on one plan: the last save wins. |

### Performance (✅ release build)

| # | Problem | Measured |
|---|---|---|
| 24 | `Project::reaches` (the cycle check on link) is O(n²) per link, so linking a chain is O(n³). | 1,000 tasks: 3.6 s; 2,000 tasks: 28 s. |
| 25 | Leveling is at least O(n³): it re-sorts, rebuilds the load and runs a full `recalculate` per delayed task. | 500 tasks: 1.4 s; 1,000 tasks: 10 s. |
| 26 | `WorkCal::between` walks one day at a time and allocates per day. One far-off date (MSO in 2299, or a typed 2062 instead of 2026) makes every recalculation slow. | 2,000 tasks: 10.6 s per edit, so the app effectively hangs. |
| 27 | Each undo step is a full `Project` clone, kept 200 deep with no memory budget. Near the size limit this can exhaust memory. | Not measured; about 10 GB worst case. |

### P2: minor issues

**MCP and security**
- The DNS-rebinding check accepts `127.evil.example`, because it uses `starts_with("127.")`; only the bearer token still protects the server (`http.rs:148`). ✅
- Oversized ids are truncated to small ones (`u64 as u32` in `time.rs:154`, `assignments.rs:76`, `dependencies.rs:347`; `as u16` in `tasks.rs:581`). For example, entry `4294967297` deletes entry 1.
- Undo and redo through MCP are recorded as `ChangeSource::User` (`workspace.rs:155, 165`).
- `refresh_external_links` skips undo, attribution and the dirty flag (`dependencies.rs:396`).
- `hours_per_point` accepts `"NaN"` and tiny values, which store 0 (`documents.rs:340`).
- JSON-RPC:
  - It accepts `id:null` and object ids, and a missing `jsonrpc` field.
  - It accepts batches under 2025-06-18, where the spec removed them.
  - It ignores the `MCP-Protocol-Version` and `Mcp-Session-Id` headers.
  - The attach bridge never answers a failed batch line.
- The HTTP server spawns a thread per request before the auth check, and the body read has no timeout (`http.rs:115, 246`).
- `--http` mode prints the bearer token to stderr (`cli.rs:121`), which conflicts with the CLAUDE.md rule.
- External files are loaded with the workspace lock held, which freezes the UI on slow disks.

**Files**
- CSV export:
  - Cells starting with `= + - @` are not neutralised (formula injection).
  - There is no UTF-8 BOM, so Excel garbles non-ASCII text.
  - Only tasks are exported (`app.rs:233-250`).
- Atomic saves replace a symlinked plan with a regular file, drop group ownership and ACLs, and overwrite read-only files.
- On load:
  - `sanitize` keeps links and members that point at missing tasks.
  - Duplicate external-project UUIDs are accepted.
  - `ensure_external_task` doesn't check the project id.

**Engine**
- `Lag::parse("3 minute")` fails (the `e` elapsed suffix is matched first).
- A manual task shows its manual start instead of its actual start.
- Whether a 0-length task becomes a milestone depends on `new_tasks_auto`.
- `add_summary_over` mis-parents non-contiguous or nested selections.
- `log_time` on a weekend uses the base calendar, not the task calendar.

**App**
- Actual Start/Finish can't be cleared in Task Info, and an invalid Fixed Cost silently becomes 0.
- A Gantt drag gets stuck when the mouse is released outside the window.
- Shift+Tab moves right.
- Column widths leak between tables that have the same number of columns.
- The History toolbar button never shows as active (`menubar.rs:425` reads `st.show_history`).
- Dark mode: the Milestones chips have white text at about 2.2:1 contrast, and the "MCP live" green is hard-coded (`menubar.rs:87`). The contrast test only covers ACCENT and TITLE_BAR.
- Paste:
  - It drops links between the pasted tasks and their assignments.
  - It keeps the source document's calendar ids.
  - Move Up/Down moves only the first selected task.
- Shortcuts:
  - Shortcuts act on the hidden document behind the Start Page or the save prompt.
  - Restoring a recovery copy of an open file binds two documents to the same path.
- The app uses raw `chrono ± Duration` in 44 places (rule: `calendar::shift`/`checked_*`).
- `clamp(0, ncols-1)` would panic on a grid with no columns.
- The Timesheet totals row accepts edits and silently drops them.

## 3. Suggested order

1. **One small P0 batch:**
   - Bugs 1 (attach chunking), 3 (clipboard keys), 4 (no-op commits), 5 (Save As) and 8 (Units).
   - Each comes with a regression test, as CLAUDE.md requires.
   - Each is a contained change.
2. **Document safety:**
   - Bug 2 (bind each dialog to its document id).
   - Bugs 6 and 7 (external path policy; agent discard).
   - Bugs 9 and 19 (modification-time check on save; a timer-driven recovery tick).
3. **Engine correctness:** bugs 10–18. Each gets a parity test in `ms_parity.rs` with its Microsoft source.
4. **Performance:** bugs 24–26 (an incremental reachability check, smarter leveling, and arithmetic over whole weeks in `between`). Add 2,000-task cases to the speed gate.
5. **Parity features, by user impact:**
   1. Column picker, custom fields, sort and group.
   2. Print/PDF.
   3. Status date and Update Project.
   4. Network Diagram.
   5. Multiple baselines.
   6. Task splitting and recurring tasks.
   7. Board view.
   8. Near the end: MSPDI import/export (approved).
